Before Accepting Done

Rule: no artifact plus no route check equals not done.

1
Artifact exists.

There is a reviewable file path, URL, screenshot, diff, dashboard, message ID, or receipt. No artifact means not done.

2
Exact route was exercised.

The proof covers the real surface, not a nearby proxy. Local config proof does not prove a live channel, checkout, browser path, or cron destination.

3
Verification output is named.

The closeout names the command, observed result, HTTP status, screenshot, readback, test output, or manual inspection result.

4
Delivery state is clear.

The artifact is where the reviewer, buyer, client, or operator can actually access it. A file existing only in a hidden runtime is partial.

5
Side effects are declared.

The closeout says whether anything was posted, emailed, messaged, published, deployed, purchased, charged, deleted, or changed in production.

6
Authority and caps are recorded.

Any public, send, spend, publish, or checkout action has an activation contract: identity, target, copy, cap, tracking, kill rule, and route proof.

7
PASS, FAIL, or PARTIAL is explicit.

Do not accept soft language like "should be fixed" or "ready." If evidence is missing, the state is FAIL or PARTIAL.

8
Next owner is named.

When the result is PARTIAL, the closeout names the next action, owner, blocker, and review date. Otherwise the task will disappear into a false green state.
